## 3. 五組 CTest 實際內容

1. `protocol`：原有 26 項 parser、CRC、ACK 與教學狀態機檢查。
2. `signing`：六項簽章、重播與接收政策檢查。
3. `udp_integration`：原有十個跨行程 UDP 情境。
4. `router_integration`：獨立雙 client 的遙測 fan-out 與命令回覆。
5. `px4lite_udp_integration`：原有 PX4-Lite 模組的正常飛行／失聯降落兩個情境，另含遙測與 Arm／Disarm。

第五組只有設定 `PX4LITE_ROOT` 時才建立。未設定時，少一組是選擇性依賴的結果，不能把它算成驗過原專案。真 PX4 runner 另行執行，不在這五組短回歸測試中。

## 4. 真 PX4 的三個場景

每個場景重新啟動一個自己的 PX4 子行程，使用新暫存工作目錄，參數設定與 Mission 內容不沿用既有專案。結束時透過 `shutdown` 清理；逾時只終止本 runner 啟動的 process group。

### 正常飛行

Lab 01 至少收到姿態，Lab 02 的 Arm／Disarm 都有 ACCEPTED 與新 heartbeat 狀態。Lab 05 以三維位置與速度門檻觀察升高 2 m、向北 2 m、返回；再以真正 landed state 確認落地，最後確認未解鎖。

完整輸出：[lab05 正常 log](evidence/2026-10-26/sitl/normal/4-lab05_sitl.log)、[PX4 log](evidence/2026-10-26/sitl/normal/px4.log)。最後亦查詢 `commander status`、`vehicle_local_position` 與 `vehicle_land_detected`；landed 為 true。

### Offboard 控制流失聯

明確設定 COM_OF_LOSS_T=0.5、COM_OBL_RC_ACT=4，在預送、解鎖並升高後停止 setpoint。觀察到 `Failsafe activated`、離開 Offboard、AUTO.LAND custom mode=100925440、落地與 Disarm。

完整輸出：[lab05 失聯 log](evidence/2026-10-26/sitl/loss/2-lab05_sitl.log)、[PX4 log](evidence/2026-10-26/sitl/loss/px4.log)。這個測試沒有把 client heartbeat 一起停止，因此能區分 datalink presence 與 Offboard control presence。

### 進階服務

在未解鎖的私有模擬端完成：

```text
PARAM_INT SYS_AUTOSTART=10040
PARAM_WRITE_READ_RESTORE original=0.5
TIMESYNC samples=8 ...
MISSION_UPLOAD_DOWNLOAD_CLEAR items=3 (not executed)
SERVICES_PASS
```

這次八筆 TIMESYNC 的最大 RTT 約 0.120416 ms；clock offset 很大是兩個時間域的差，不是 UTC 時鐘錯誤的判定。Mission 沒有起飛執行，驗證的是傳輸與讀回。完整輸出：[服務 log](evidence/2026-10-26/sitl/services/2-lab07_services.log)、[JSON 結果](evidence/2026-10-26/sitl/services/result.json)。

## 5. 本次發現的問題與修正

- WSL 能啟動，但 systemd user session 警告與初次呼叫延遲仍存在。使用已開啟的 shell 執行原生程式，沒有重設發行版或永久系統設定。
- PX4 rootfs 參數需要指向 build 裡的 `etc`，而不是整個 build 根目錄；修正 runner 後成功啟動。
- Windows 不能覆寫正在執行的 bridge EXE。編譯時短暫停止本次自行啟動的 bridge，完成後恢復；QGC 本身保留開啟。
- Mission 第一次上傳被實際 PX4 拒絕。檢查該版本 `mavlink_mission.cpp` 的參數驗證後，修正 Land 的 param2：它是 precision landing 選項，不能沿用 waypoint 的 0.5 m acceptance radius。重新上傳、下載與清除全部通過。
- 新 adapter 在來源 sysid 的縮窄轉換曾出現編譯警告，已改為明確轉型；最後 Linux build log 沒有新增 warning／error。

## 6. 範圍與剩餘限制

已完成原學習路線後續的**可執行入門範例**；尚未把它擴成完整飛控產品。具體限制如下：

- 沒有真機、UART、Gazebo 3D 或視覺感測器實驗；沒有 v1.17.0 的獨立驗證、MSVC 或長時間 soak。
- QGC 目前連接的 Lab 04 最小 bridge 仍沒有完整 metadata／參數／任務服務；它的 Not Ready 不會因為真 PX4 測試成功而消失。QGC 自身的 Arm 操作尚未另做 GUI 驗證。
- PX4-Lite 直接重用原 Commander 與控制／物理模組；原 Pub/Sub 類別嵌在 main，新的 FIFO／最新狀態 topic 是 adapter 的橋接邊界，不是假稱已接真正 uORB。估測目前使用模擬真值。
- 服務 Lab 沒有完整參數列表快取、所有參數型別、Mission pause/resume／部分更新／所有重傳故障情境；恢復參數與任務隔離限 runner 的私有模擬環境。
- router 是單載具、固定兩端的未簽章 star topology，沒有完整動態路由、迴圈抑制與多載具管理。實際 QGC＋C++ 同時操作的 GUI 情境尚未另外實測，自動測試使用兩個獨立 C++ client。
- signing 已驗證官方 library 的行為，但沒有配置 QGC ↔ PX4 的實際簽章鏈路、秘密儲存、金鑰輪換或重啟後時間管理。
- client 仍是一筆 outstanding command，STATUSTEXT 僅印每個收到的 chunk，沒有完整長文字重組。ACK 的同 ID 遲到回覆歧義與嚴格即時控制需求仍需後續產品設計。

本報告保留這些界線，避免把「教學範例可執行」與「所有協定與部署情境已完成」混為一談。
