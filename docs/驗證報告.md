## 重現指令

在專案根目錄執行：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 1
ctest --test-dir build --output-on-failure -V
```

`ctest -N --test-dir build` 應列出 `protocol` 與 `udp_integration`。若缺少後者，先讓 CMake 找到 Python。CTest log 自動保存在 build 下；需要留存時複製到另一個檔名，避免覆蓋本報告附件。

## UDP 跨行程整合

來源：[integration.py](../tests/integration.py)。作業系統選擇臨時埠，啟動 bridge 並等 BRIDGE_READY，接著執行編譯後 client。檢查退出碼、關鍵輸出與部分 bridge log。每個情境結束時清理該測試啟動的 bridge 行程。

| # | 情境 | 驗收依據 | 結果 |
| --- | --- | --- | --- |
| 1 | Lab 01 遙測 | 收到指定 sysid/compid HEARTBEAT、ATTITUDE 與 summary | 通過 |
| 2 | Lab 01 對端退出 | 已收到 heartbeat，之後回報 HEARTBEAT_TIMEOUT，退出碼 3 | 通過 |
| 3 | Lab 02 Arm / Disarm | 都有 ACK，且新的 heartbeat 確認 armed=1 / 0 | 通過 |
| 4 | deny | 印 DENIED 與 result=2，退出碼 3 | 通過 |
| 5 | drop-first | 第二次發送成功；bridge 收到 confirmation=1 | 通過 |
| 6 | silent-ack | 最多三次發送；COMMAND_TIMEOUT，退出碼 3 | 通過 |
| 7 | no-state | 收到 ACCEPTED，但 STATE_CONFIRM_TIMEOUT，退出碼 4 | 通過 |
| 8 | progress | 先 IN_PROGRESS 再 ACCEPTED；沒有 attempt=2 | 通過 |
| 9 | spoof | 錯來源、錯收件者、錯命令 ACK 沒造成誤成功 | 通過 |
| 10 | Lab 03 + Lab 04 | 預送、切模式、Arm、位置達標、停止 SP、模式失聯、Disarm | 通過 |

最後一項的 client 使用三秒移動觀察；驗證 `POSITION_REACHED=1` 與 `OFFBOARD_LOSS_CONFIRMED`，bridge 同時出現 `OFFBOARD_LOSS -> HOLD`。這能證明本模型的資料流與狀態流程成立，無法證明真實飛控的控制品質。

## 驗證中發現並處理的問題

第一次預設平行編譯遇到 GCC out-of-memory。改用 `--parallel 1` 後，所有 target 成功建立；重現指令已採用這個設定。

第一次 UDP 整合測試在 client 尚未啟動的時間窗遇到 Winsock `WSAECONNRESET`（10054）。UDP 的這個錯誤可能表示先前送出的封包收到 ICMP Port Unreachable，見 [Microsoft recvfrom 文件](https://learn.microsoft.com/en-us/windows/win32/api/winsock/nf-winsock-recvfrom)。現在此接收情況會返回事件迴圈，讓 discovery / heartbeat 的期限判斷對端不存在；其他 socket 錯誤仍回報。修改後重新編譯並重跑完整兩群測試，全數通過。

## 尚未驗證與功能限制

- 沒有完成真正 PX4 v1.17.0 SITL 的連線、Arm 或 Offboard 飛行驗證。工作區只有原始路線，沒有 PX4 build；嘗試啟動現有 Ubuntu WSL 時失敗，回報 `Wsl/Service/RPC_S_CALL_FAILED`。
- POSIX socket 分支已有原始碼，但本次未在 Linux 編譯或執行；MSVC 也未測。
- 沒有連接原本的 PX4-Lite / uORB 專案。提供的是同步、獨立的教學 Commander 介面及移植作業。
- 沒有 UART、真實網路或硬體測試；沒有量測控制週期 jitter、網路擁塞、長時間 soak、多機路由與真實飛行穩定性。
- 沒有實作 Parameter、Mission、Signing、TIMESYNC 與完整 STATUSTEXT / events；教學文中列為後續延伸。
- client 是單執行緒、固定單一 UDP 對端、一次一筆命令。ACK 缺少交易 UUID 帶來的遲到同 ID 回覆歧義仍存在。
- 模擬失聯只退出 Offboard 並保持位置數值，未實作 PX4 的降落或安全決策；Lab 03 也明確限制對端種類。

真正 SITL 的操作與待驗收表列在 [教學手冊第 7 章](教學手冊.md#7-閱讀真正-px4再做-sitl-驗收)。這些項目應在對應環境補完後再新增證據，不應把 loopback 測試的成功直接當成 SITL 成功。
