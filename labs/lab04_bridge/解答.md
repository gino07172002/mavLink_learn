# Lab 04 解答與講解

這份解答對應 [練習題](練習.md)。[reference/src/main.cpp](reference/src/main.cpp) 保存未修改的完整程式；下列文字解釋修改後應如何判斷。

## 練習 1：修改 pitch 並重啟

接收端不需改定義或重新生成 headers。欄位內容改變，不是 message 格式改變。Inspector raw pitch 約 0.2 rad，Lab 01 顯示約 11.46°。

## 練習 2：修正 rollspeed

應送 0.1*cos(t) rad/s。pitch、yaw 固定，所以它們的 rate 仍為零。roll=0 時可能正快速通過中點；roll 在極值時 rollspeed 約零。

## 練習 3：命令與業務分離

通訊端處理線路與來源，Commander 接受內部命令並決策；本模型 Arm 是設定狀態，具冪等性。真實相機拍照等操作不可直接假設同樣冪等。

## 對話講解整理：一行 pack() 到底做了什麼？

把發送姿態那一行展開看，基準程式是：

```cpp
mavlink_msg_attitude_pack(
    1, 1, &msg,
    lab::millis(start),
    0.1f * std::sin(t), 0.05f, 0.2f,
    0, 0, 0
);
udp.send(msg);
```

| 位置 | 意義 |
| --- | --- |
| 第一個 `1` | 發送者 system ID |
| 第二個 `1` | 發送者 component ID |
| `&msg` | 產生的訊息物件放到哪裡 |
| `millis(start)` | 本程式開始以來的毫秒數 |
| 中間三個 float | roll、pitch、yaw，單位 rad |
| 最後三個 float | rollspeed、pitchspeed、yawspeed，單位 rad/s |

前兩個 ID 說「誰發的」，不是收件者。這個 ATTITUDE payload 沒有 target IP／port；傳輸目的地由 `Udp` 設定。

`pack()` 使用該訊息定義處理欄位、訊息標頭與 CRC；不要把 C++ struct 的記憶體直接拿來傳送。接下來 `udp.send(msg)` 會呼叫共用 `encode()`：

```text
msg → mavlink_msg_to_send_buffer() → bytes → sendto() → 對方 IP:port
```

因此 MAVLink 負責訊息表示與 frame 格式，UDP 負責把 bytes 送往指定網路端點。你可以在 [共用 helper](../../common/include/lab.hpp) 直接找到這兩步。

## 對話講解整理：先預測，再看地面站

目前姿態是合成訊號，不是感測器輸出：

```cpp
roll  = 0.1f * std::sin(t);
pitch = 0.05f;
yaw   = 0.2f;
```

QGC Inspector 讀原始 rad，所以 roll 變動、pitch 與 yaw 固定。Lab 01 在顯示時另乘 `180 / π`，才變成 degree。0.1 rad 約 5.73°，0.05 rad 約 2.86°，0.2 rad 約 11.46°。

基準刻意保留 roll 有變、rollspeed 卻為零的簡化，讓你練習找出資料不一致。練習後的對應呼叫應該是：

```cpp
mavlink_msg_attitude_pack(
    1, 1, &msg, lab::millis(start),
    0.1f * std::sin(t), 0.2f, 0.2f, // pitch 練習改成 0.2
    0.1f * std::cos(t), 0, 0         // 修正 roll 的導數
);
```

完整可執行程式仍在 `src/main.cpp`；上面是指定欄位的修改片段。先做一次 pitch 修改，再做導數修改，避免同時改太多而分不清結果。

## 為什麼重做要重啟？

磁碟上的新 EXE 不會改變已經在跑的舊行程。bridge／模型也會保留上次 armed、mode、位置等狀態；重啟新的練習對端，才能把改程式的效果與舊狀態分開。

重設工具只還原已列在基準 manifest 裡的檔案，會先保存你的當前版本；自己的筆記和新增檔案保留。若改過共用 helper，另用 `python scripts/reset_lab.py common` 還原，並重新建立所有受影響的 target。
