# Lab 01 解答與講解

這份解答對應 [練習題](練習.md)。[reference/src/main.cpp](reference/src/main.cpp) 保存未修改的完整程式；下列文字解釋修改後應如何判斷。

## 練習 1：固定 pitch：0.05 → 0.2

QGC Inspector 的原始值約 0.2 rad；Lab 01 會顯示約 11.46°。原始 0.05 rad 約為 2.86°。只重新編譯而不重新啟動舊 bridge，畫面不會用到新程式。

## 練習 2：把收包路徑畫出來

recvfrom 得到 bytes，parser 驗證 frame，Client 篩選來源，observer 解碼 payload，最後在顯示邊界把 rad 轉 degree。沒有直接把 UDP buffer 當作姿態 struct。

## 練習 3：失聯與資料新鮮度

已連上後最後 heartbeat 超過約兩秒：HEARTBEAT_TIMEOUT、退出碼 3；完全找不到對端：DISCOVERY_TIMEOUT、退出碼 2。停止姿態但繼續 heartbeat 是另一種資料失效，本版不會把它當成 heartbeat timeout。

## 對話講解整理：看見資料後，還要自己追接收端

QGC 看到三個訊息時，先問它們各自回答什麼：HEARTBEAT 回答「誰還在線、目前部分狀態」，ATTITUDE 回答「姿態」，LOCAL_POSITION_NED 回答「本地位置與速度」。一個訊息更新，不表示另一種資料也新鮮。

再看本 Lab：

```cpp
if (msg.msgid == MAVLINK_MSG_ID_ATTITUDE) {
    mavlink_attitude_t attitude{};
    mavlink_msg_attitude_decode(&msg, &attitude);
    // 姿態在這裡仍是 rad；輸出時才轉換。
}
```

此時 callback 已拿到 parser 確認過的 message。不要在收到 UDP bytes 時就直接讀 roll，因為一個 datagram 可能含多個 frame，也可能遇到錯誤 frame 或片段。

接下來可重複練這五步，進度不以「範例作者已經跑過」取代你自己的練習：

1. 修改 Lab 04 的 pitch，預測 QGC 與 Lab 01 的單位差別。
2. 把 `recvfrom → parser → decode` 的實際函式連起來。
3. 停止 bridge，比較已連上後 timeout 與一開始 discovery timeout。
4. 到 Lab 02 做正常命令、拒絕、ACK 遺失，分開觀察 ACK 與狀態。
5. 到 Lab 05 重現真正 PX4 SIH，再回頭對照內部原始碼。

## 為什麼重做要重啟？

磁碟上的新 EXE 不會改變已經在跑的舊行程。bridge／模型也會保留上次 armed、mode、位置等狀態；重啟新的練習對端，才能把改程式的效果與舊狀態分開。

重設工具只還原已列在基準 manifest 裡的檔案，會先保存你的當前版本；自己的筆記和新增檔案保留。若改過共用 helper，另用 `python scripts/reset_lab.py common` 還原，並重新建立所有受影響的 target。
